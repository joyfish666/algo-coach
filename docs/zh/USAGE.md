# USAGE

面向使用者的安装、启动与页面说明。文档随功能落地持续补充。

## 安装

要求 Python ≥ 3.10（Node.js ≥ 18 仅在从源码构建前端时需要）：

```bash
git clone https://github.com/joyfish666/algo-coach.git
cd algo-coach
pip install -e .
cd web && npm install && npm run build && cd ..
```

构建完成后 `coach` 直接托管前端页面，日常使用不再需要 Node。

## 启动

```bash
coach
```

- 服务仅绑定 `127.0.0.1`，默认端口 8000，被占用自动顺延。
- **单实例守卫**：已有 coach 实例运行时拒绝重复启动并提示地址；崩溃残留的锁文件自动接管。
- 横幅显示最终实际 URL；服务就绪后自动打开浏览器。
- 首次启动进入 `/setup` 引导页。
- 参数：`--port`（首选端口）、`--no-browser`（不自动开浏览器）、`--debug`（详细日志）。
- 配置优先级：CLI 参数 > 环境变量 > 配置文件。`ALGOCOACH_*` 环境变量在启动时校验，
  格式错误会拒绝启动并指明是哪个变量（退出码 2），而不是运行中随机报错。
- 数据目录：`~/.algocoach/`（POSIX 下权限收紧为 600；Windows 依赖用户目录保护）。

**Windows 双击启动**：直接双击项目根目录的 `start.bat`——自动切换到项目目录、
用 `.venv` 里的 coach 启动服务并在就绪后打开浏览器。**重复双击也不会出问题**：
已有实例在运行时（包括正在等待空闲退出的实例），再次双击会直接为它弹出浏览器
而不是报错，也不会启动第二个服务。**关闭网页后服务自动退出**：每个打开的页面
每 20 秒向服务发送一次心跳，关闭全部标签页后约 2 分钟（等同步完成才退出）服务
自动关闭、窗口随之消失；浏览器冻结后台标签不会误杀（回到页面会立即补一次心跳）。
手动 `coach` 启动默认不启用该行为，需要时用 `coach --idle-exit 分钟数` 开启。

`start.bat` 的前提（一次性，脚本缺什么会提示什么，不会闪退）：
① 已按上文完成安装（项目 `.venv` 或 `coach` 在 PATH 上均可，脚本优先用 `.venv`）；
② 前端已构建（`web/dist` 或 `server/webdist` 存在）。只克隆仓库直接双击是不行的。

## /setup 向导

分步配置：

1. **Cookie**：默认简易模式只需填两个值——浏览器登录 leetcode.cn 后按 F12 →
   「应用/Application」→ 存储 → Cookie → https://leetcode.cn，把 `LEETCODE_SESSION`
   和 `csrftoken` 两行的「值」分别复制粘贴进来，点校验通过后下一步；
   也可切换「整串粘贴」模式直接贴完整 Cookie 头。
2. **偏好**：默认刷题语言与界面主题。

LLM/AI 配置**不在向导里**：它独立放在「设置」页的「AI（LLM）」卡片，与 Cookie 互不影响，
随时可改（见下文设置页说明）。

Cookie 失效后任意页面会弹出底部横幅引导重新配置，也可在设置页点击「更新 Cookie」。

## 页面说明

| 路由 | 页面 | 说明 |
|---|---|---|
| `/problems` | 题库列表 | 「同步题库」拉取全量题库（4400+ 题，按限速约 2–3 分钟，请耐心等待）；状态（已通过/尝试过/未做/收藏）/难度/标签/关键词筛选、随机一题（在当前筛选结果内随机）、紧凑/舒适密度切换；难度/标签筛选与 URL 参数联动，浏览器前进后退可还原 |
| `/problem/:qid` | 答题工作台 | 题面渲染 + CodeMirror 编辑器（语法高亮随浅色/暗色主题自动切换）+ Run/Submit + 自定义用例 + 笔记 + 收藏 + AI 对话侧边栏 |
| `/daily` | 每日一题 | 今日题目卡片直达工作台 |
| `/history` | 提交历史 | 本地归档的每一次提交：时间/题目/语言/结果（本地化文案，与工作台判定面板一致）/用时/内存，可按题目过滤；WA 对比与 CE/RE 详情可展开；筛选无结果与「从未提交」显示不同提示 |
| `/analyze` | 分析仪表盘 | 解题统计、标签掌握度（悬停可见完整标签名与做题数）、推荐练习、AI 薄弱点报告（生成失败不影响统计展示；报告生成后可一键重新生成） |
| `/settings` | 设置 | 外观（界面语言/主题/调试模式）、默认刷题语言、**AI（LLM）卡片**（API Key / 接口地址 / 模型 / 思考模式，独立于 Cookie，带「测试连接」一键连通性探测）、Cookie 状态与管理、数据清除（进阶项 LLM 超时 `llm_timeout` 仍经 API 或 config.toml 设置，范围 [5, 600] 秒） |

同步进度是全局的：同步进行中切换页面不会丢失进度显示，刷新页面后也会自动重新接管正在进行的后端同步。操作反馈统一出现在右上角 toast——成功提示几秒后自动消失，错误提示会驻留直到你关闭它（避免「失败了你却没看见」）。

## 工作台要点

- **自由布局**：题面/编辑器之间的竖向分隔线、编辑器与自定义用例之间的横向分隔线
  均可拖拽调整大小，比例自动记忆；题面与标签/难度 chip 可点击跳转到筛选后的题库。
- **语言切换**：支持 cpp / python3 / java，未落盘的语言首次切换时需联网拉取模板；
  已落盘语言可断网复习。
- **Run 模式**：远程执行用例（需联网，本地不编译），不进入站内提交历史；
  默认运行全部官方示例用例；勾选「使用本地自定义用例」时使用面板编辑的 testcases.txt。
  若提示「调试服务暂不可用」为 leetcode.cn 调试服务偶发内部错误，稍后重试即可。
- **Submit 模式**：正式提交进入站内提交历史，判定完成自动归档到本地 JSON Lines，
  题库列表会显示「✓已通过 / 尝试过」徽章。判定期间结果区会显示计时提示；
  正式提交最长约 2 分钟，请勿关闭页面。
- **快捷键**：`Ctrl+Enter` 运行，`Ctrl+Shift+Enter` 提交（按钮旁常驻提示）；
  判定进行中运行/提交/语言切换互斥；AI 面板打开时 `Esc` 收起。
- **保存机制**：代码与笔记均停止输入约 1–2s 自动写盘；离开页面或切换题目时未保存的
  内容会立即冲刷保存（代码、笔记都算，不会丢最后一次按键）；异常退出后下次打开会提示恢复代码快照。
  瞬时失败（如网络抖动导致保存/判定失败）只会在 toast 提示，不会替换掉整个工作台界面。
- **重开续用上次语言**：再次打开题目时自动回到上次实际使用的语言与对应代码——
  即使它不是设置的默认刷题语言（比如用 Python 做完的题，重开就是 Python）。
- **收藏**：题库列表行内 ☆ / 工作台标题旁星标均可切换，配合列表页「收藏」筛选
  形成个人错题本/重做清单。
- **AI 教练**：右下角悬浮球打开（`Esc` 关闭），按住标题栏可拖动到任意位置，
  窗口尺寸变化后自动回到可视范围内；对话上下文（当前题目 + 最近判定）自动附带，
  勾选「附带当前代码」可把编辑器内容一并交给 AI（并标注当前语言）；
  标题栏「清空对话」可一键重置当前会话；
  未配置 LLM 时面板会显示引导横幅（直达设置页），发送按钮保持禁用；
  回复按 Markdown 渲染（粗体/列表/代码块正常显示，模型输出中的 HTML 一律转义）；
  回复语言跟随界面语言（中文界面得到中文回答，英文界面得到英文回答；
  引用的中文题面保持原文）；切换题目时对话自动清空，不携带上一题的上下文。

## AI（LLM）配置

在「设置 → AI（LLM）」卡片独立配置，与刷题 Cookie 互不影响：

- **字段**：API Key（已保存时留空表示不修改）/ 接口地址 Base URL / 模型名。
- **测试连接**：点击后向后端配置的端点发一个极小的 ping 请求（`max_tokens` 限幅），
  成功显示模型名与实测延迟，失败显示服务端错误原文（如 401 bad key）。
  测试使用表单当前值（未填的字段回退已保存配置），**测试不会保存**——确认可用后记得点「保存」。
- **思考模式**：`跟随模型默认 / 关闭思考 / 开启·低 / 开启·中 / 开启·高`。
  各服务商的思考参数没有统一标准，本应用按最通用的 OpenAI 兼容约定发送：
  关闭 → `enable_thinking: false`；低/中/高 → `enable_thinking: true` + `reasoning_effort`；
  「跟随模型默认」不发送任何额外字段（对严格校验的服务商永远安全）。
  你的服务商若不认这些参数，保持默认档即可，或用「测试连接」验证。
- 环境变量 `ALGOCOACH_LLM_THINKING` 可覆盖思考模式（取值同上，启动期校验）。

## 调试模式

遇到界面异常时：设置 → 外观 → 勾选「调试模式」（或 URL 加 `?debug` 参数，值不限）。
左下角会出现 DEBUG 悬浮条，自动捕获前端报错；点「复制日志」发给开发者即可。
后端详细日志可用 `coach --debug` 启动查看。

## 常见报错对照表

| 现象 | 含义与处理 |
|---|---|
| 403 / 提示 Cookie 过期 | Cookie 已失效（重新登录会触发轮换），按引导重新粘贴最新值 |
| 提示「打开题目并选择该语言」 | 该语言模板尚未落盘且当前离线，联网后打开题目并选择该语言即可 |
| 付费题标记 | Premium 题目无法拉取题面/判定，优雅跳过 |
| 429 / 触发限速 | 已自动退避；频繁出现请降低操作频率或调整请求间隔配置 |
| 「结果未知，请在站内确认」 | Submit 判定轮询超时但提交已进入站内历史，归档已记录 submission_id 可追溯 |
| 「调试服务暂不可用」 | Run 时 leetcode.cn 调试服务偶发内部错误，稍后重试即可 |
| 「请求超时」 | 前端对每个请求设有截止时间（长判定/LLM 请求放宽至 150s），超时说明后端无响应：确认 coach 进程仍在运行 |
| 「无法连接本地服务」 | 请求根本没发出去（后端进程退出、机器刚唤醒等），先确认 coach 是否在运行；界面不再显示英文浏览器原文 |
| 「后端已重启，同步被中断」 | 同步进行中后端进程退出过；重新点击「同步题库」即可 |
| 「判定成功，但本地归档写入失败」 | 站内判定已完成且无法重放，仅本地归档落盘失败（磁盘满/被占用）；这条提交不会出现在提交历史，修复磁盘后可从站内重新导入 |
| HTTP 500 / 其他异常 | 开启调试模式复制前端日志，并用 `coach --debug` 查看终端 traceback |

## FAQ

- **数据存在哪里？** 全部在本地 `~/.algocoach/`（题库缓存 problems.json、练习归档
  submissions.jsonl、题目工作区 workspace/、配置 config.toml），无云依赖。
  设置页「数据与隐私」会显示实际路径，并提供**一键清除全部数据**按钮——为防误触，
  需在输入框中输入 `DELETE` 确认后才会执行（清除后回到未配置状态，需重走向导；
  浏览器里的代码草稿快照会一并清除，主题/语言等界面偏好保留）。
- **界面语言和题面语言的关系？** 题面以 leetcode.cn 返回为准（绝大多数为中文），
  界面语言仅影响 UI 文案；接口错误提示会按界面语言自动翻译。
- **Cookie 明明复制对了却提示失效？** 重新登录 leetcode.cn 会使旧会话立即失效
  （服务端轮换）。请以**最新一次登录后**复制的值为准；复制时确认行名是
  `LEETCODE_SESSION` 与 `csrftoken`。
